# Normal-control browser evidence

Prepared harness: `node scripts/network/browser-championship.mjs`.
Preparation commands `--describe` and `--self-test` do not launch a browser or contact a service. The self-test uses synthetic report fixtures only; it is not multiplayer evidence.

Do not run the browser matrix until the parent freezes the integrated production build, supplies its URL and fingerprint manifest, and releases the shared GPU from asset inspection. The existing parent browser/driver is not used. Runtime arguments are `--url URL --manifest MANIFEST_PATH --revision EXPECTED_REPORT_REVISION`; `--pairs lion:wolf` limits a diagnostic pilot and does not satisfy the nine-pair gate. The default covers all nine ordered species pairings and a complete rematch of the first pair. After a successful pilot/rematch, a separate explicit eight-pair remainder can use `--rematch none`; the parent must review the combined evidence under the same frozen fingerprint. A full nine-pair invocation cannot disable its rematch.

The production build must use ordinary browser downloads (`NEXT_PUBLIC_QA_CAPTURE_ORIGIN` absent). The harness launches two isolated installed Chrome profiles with `channel: 'chrome'` and `headless: true`. It uses selection/lobby/action buttons, normal keyboard presses, and visible phase/progress/health/windup/opening text. It does not import game code, evaluate private state, patch clocks, route network responses, change physics or install a control hook.

Each role performs race steering and leaps, a 330 ms reaction to an observed windup, evade, approach and strike response, and further committed attacks. A round passes only when downloadable authoritative reports show at least two race leaps, actual strikes, at least one successful evade, an actual counter inside the earned opening, and received damage for **both** roles, with identical final scoring and players. A pose, ordinary late reply or input acknowledgement is insufficient. Failed exchanges remain in the timeline/screenshots; no failed attempt is silently retried as a new match. Two consecutive failed pairings stop the matrix for diagnosis.

The input plan is an integration exercise, not a balance contest: race steering holds are 180 ms for the host and 260 ms for the guest, and the finishing strike exchange begins with the host. Win rates from this matrix cannot measure role fairness or species balance. The 330 ms delay begins after automation reads the visible cue; completed clicks can take longer under machine load and their actual elapsed times are saved.

Evidence directories are exclusive timestamped `run-*` folders. They include the source manifest, initial/race/results UI downloads, canvas recordings, UI screenshots, actual input/cue timestamps, served asset/bundle hashes and a matrix summary. Default viewport is 1100×740 with both roles recording. `--viewport 844x390 --record host` reduces shared-machine work while retaining both active clients and both reports/screenshots. This exercises a landscape layout but does not emulate native touch or a phone GPU. Both profiles are closed and their temporary cache directories removed. The source manifest and Next build identity are checked during the run. Runtime errors or served-file mismatches prevent acceptance. Original network probe/audit artifacts are not overwritten.

After each pair's browsers close, every raw recording is fully decoded with ffmpeg. A portable H264 CRF25/960px/30fps/AAC review MP4 is then produced and fully decoded again. Raw/output hashes, sizes and ffprobe metadata are retained beside it. Only after both clean decodes is this run's raw duplicate removed. Encoding uses two threads and does not overlap the harness's browser measurements; unrelated parent work can still load the host, so these remain functional observations rather than controlled performance results.

This is **same-machine online-service smoke**. Both clients share one computer and network. Headless Chrome, two renderers and canvas recording impose their own load. Native touch, physical-iPhone sustained performance, separate-network play, human reaction/feel and general latency fairness remain unverified. Canvas recordings exclude DOM controls/HUD; the screenshots and public report evidence supply that separate context. Each sampled reaction is measured from when automation observed the visible cue, not from an inferred authoritative event timestamp.

After all subsets finish, `node scripts/network/verify-browser-evidence.mjs RUN_DIRECTORY...` independently re-reads the saved public reports, re-derives both-role action counts and result equality, checks all nine ordered pairs plus a full rematch, verifies frozen identity and media hashes, and writes a fresh aggregate file. It never launches a browser or contacts a service. It fails on incomplete coverage rather than treating a passing subset as the matrix. Visual acceptance is separate: frozen combat captures exposed detached Lion/Wolf/Unicorn tails, and that defect remains explicit in the aggregate even if all gameplay checks pass.
