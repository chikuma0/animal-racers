# Runtime capture
Use the in-game Performance report panel for non-mutating measurements and canvas recordings. This is observable user tooling, not a phase-jump/CPU/control cheat. A capture of scenery is not proof of normal-control completion; pair recordings with scenario notes and visible result contributions. Physical-phone user agent, OS, device model, thermal conditions and test duration must be supplied by the tester.

For the local QA worktree only, start `node scripts/qa/capture-server.mjs` and set `NEXT_PUBLIC_QA_CAPTURE_ORIGIN=http://localhost:3014` before building the app on localhost:3013. Capture/measurement buttons then write to docs/production/evidence. The sink binds127.0.0.1, accepts only the localhost:3013 Origin, allows bounded media/JSON filenames and never overwrites a file. It has no simulation-control API. Do not enable the variable on any deployed build; ordinary browsers download files instead. Stop the sink after capture.

Canvas recordings started after the audio integration include the original in-game mix, without microphone access. Earlier Cycle2 footage was silent. Use a separate session with recording off for performance measurement; the report records that condition. The sustained histogram has0.25ms quantile resolution up to1000ms and records the exact longest stall. Reset with Start fresh measurement before a new device/load profile.
